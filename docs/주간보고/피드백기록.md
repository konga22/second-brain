### 확인 필요

- **"RSI 방식"**: 7번(교정) 대목에서 언급하신 것으로 기억. 설계서에는 Recursive Self-Improvement(검증 에이전트가 놓친 실수로 검사 기준을 스스로 고침)로 해석해 넣었다. 해석이 맞는지 여쭙는다.
- **"데프/def"(?)**: 같은 교정 대목에서 "괜찮은 방식"이라고 하신 것으로 기억(2026-11-05 사용자 회상, 정확한 단어 불확실). 가장 가까운 후보는 **diff**(수정 전후 차이를 줄 단위로 남기는 기록)다. 맞다면 교정할 때 "AI가 쓴 답 → 사용자가 고친 답"을 diff로 실수 노트에 남기고, 검증 에이전트가 그 diff를 근거로 규칙을 만드는 방식이 된다. 확인 전까지 설계서에는 넣지 않는다.

### 메모

- 3번에서 사용자가 "웹은 홍보용"이라고 답한 대로, 2026-11-05 웹을 홍보 페이지(Astro)로만 두기로 정했다. Flutter 웹 체험판은 만들지 않는다 (설계서 v1.2).
- 교수님이 직접 작성한 질문 내역(프롬프트)을 2026-11-09 주에 보여 주시기로 함. 받으면 설계서와 대조한다.
- 2026-11-05 설계 전체 검토([설계검토_최종안](../설계검토_최종안.md) 3절)에서 피드백 9건을 다시 봤다. 6건은 그대로 동의, 3·4·7번은 결론은 같고 이유·방법을 보완했다. 설계서 v1.3 부록 A "보완" 칸에 반영.
- "def"가 diff라면 v1.3 교정 방식(diff 근거 + 회귀 시험)과 그대로 맞는다. 확인 전이지만 diff 기록은 교정 근거로 쓸 만해서 v1.3에 넣었다.
