# 교수님 세컨드 브레인 vs 우리 제품 비교분석

- **작성**: 2026-11-12 17:40 틀 작성 (우리 쪽만 채움) → 교수님 프롬프트(11/12 18:00 메일 일괄 전송 예정)를 받은 뒤 교수님 쪽을 채운다.
- **범위**: **코드는 고치지 않는다.** 비교하고 보완 계획만 세운다. 계획을 실제로 할지는 사용자가 정하고, 하기로 한 것만 설계서·개발진행으로 옮긴다.
- **근거 문서**: [피드백기록](주간보고/피드백기록.md) 11~18번(11/12 수업), [기능검토](기능검토.md) 6절(핵심 질문 K-41~K-43), [발표준비](발표준비.md) "보여 줄 숫자", [설계서](설계서.md).
- **교수님 자료 보관**: 받은 프롬프트 원본은 저장소 밖(`/Volumes/SecondBrain/교수님프롬프트/` 제안)에 두고, 이 문서에는 요지만 우리 말로 적는다. 원문을 길게 옮기지 않는다. 가져다 쓰는 아이디어는 설계서 11절에 출처를 남긴다.

## 2. 분석 방법

1. **교수님 프롬프트를 스킬 단위로 읽는다.** 스킬마다 아래 칸을 채운다.

   | 스킬·파일 | 목적 | 언제 도나 (사람이 부름 / 정해진 시각 / 자동) | 입력 | 출력·저장 위치 | 사람 확인 단계 | 토큰을 아끼는 방법 |
   |---|---|---|---|---|---|---|

2. **수업에서 들은 것(가설)을 프롬프트로 확인한다** (3절 H1~H9). 맞음 / 다름 / 프롬프트에 없음으로 표시한다.
3. **같은 축으로 대조한다** (4절 기능 대조표). 칸마다 "있음·없음·다름"과 근거(교수님은 파일·스킬 이름, 우리는 설계서 절·코드).
4. **숫자로 비교할 수 있는 것은 같은 방법으로 잰다.** 계획만 세우고, 재는 것은 사용자가 정한 뒤 한다 (9절).
5. **우리 판단과 교수님 판단이 다르면 둘 다 적는다.** 교수님 방식이 무조건 맞다고 보지 않고, 우리 실측이 있으면 근거로 붙인다.

## 6. 교수님 시스템의 최적화 방식

> 토큰·턴·사람 수고·정확도 가운데 무엇을 어떻게 줄이는지. "문서 찾기 약 10토큰"(11/07 사용자 회상)이 무엇을 센 것인지 여기서 확인한다.

비교할 우리 쪽 실측 (발표준비 "보여 줄 숫자"):

| 항목 | 우리 값 |
|---|---|
| 찾기 명령 | 10~20토큰 |
| `find` 결과 5줄 | 평균 약 480자(질문 30개 평균, 길면 약 1,000자), `show` 약 700자 |
| 찾기 방식 개선 (실측 30번) | 입력 토큰 −31%, 대화 2.9 → 2.0턴, 정답 8 → 9/10 |
| 세션 시작 안내 | 실수 노트 15개일 때 2,615자(토큰은 다시 재야 함), 세션마다 같은 글이라 캐시 재사용 |
| 관계없는 요청의 숨은 비용 | +6% (CLAUDE.md 통째로는 +151%) |
| 훅 | 노트 1만 개에서 평소 질문 42ms, 관계없는 요청 0자 |
| 결론 (토큰분석) | 토큰은 출력 글자 수보다 **대화 턴 수**가 좌우한다 |

## 7. 우리가 더 좋은 점 / 우리만 있는 기능

> 프롬프트를 받은 뒤 교수님 쪽에 없는 것만 남긴다. 아래는 후보다.

후보 (교수님 쪽 확인 전):

- **실측 근거**: 쓰는 사람 vs 안 쓰는 사람 216번 실측(지난 결정 질문 답 2 → 24번), 검색 recall@5 96.7%(질문 30개), 주입 시험 16번 중 따름 0번.
- **화면**: 뇌 그래프·정리 보드·노트 편집을 갖춘 macOS 앱. 비개발자도 지식을 보고 고친다.
- **설치**: [연동] 버튼 하나로 스킬·훅·에이전트 설치.
- **교정의 안전장치**: diff 근거, 새 맥락 검증 에이전트, 회귀 시험으로 규칙끼리 부딪힘 거절.
- **쓰기 안전**: 원자적 쓰기, 충돌 확인, `undo`, 비밀값 가림, 폴더 밖 쓰기 막기.
- **규모 시험**: 노트 1만 개에서 찾기 38ms, 그래프 첫 표시 0.78초.

## 12. 추가 분석

> 프롬프트를 받은 뒤 채운다.

- **교수님 방식과 부딪히는 우리 결정**: 평가 때 질문받을 수 있는 것(자동 저장 기본 켬, 실수 노트 바로 적용 등)과 답할 근거.
- **지식 오염 경로 비교**: 확인 전 지식이 다른 AI에게 쓰이는 길.
- **사람 수고 비교**: 확인·폐기에 드는 시간.
- **규모**: 노트 1만 개, 규칙 수백 개일 때 두 방식.
- **도입 장벽**: 설치, 비개발자, Claude·Codex 두 도구.
- **일정 영향**: 12/08까지 넣을 수 있는 것과 2단계로 미룰 것.
- **발표·보고에서 말할 것**: 교수님 방식을 참고한 점, 다르게 간 점과 이유.
