## 1. 한눈에 보기

- **교수님 것은 "설치 프롬프트"다.** Claude Code·Codex·Gemini CLI 가운데 하나에 붙여 넣으면 AI가 질문 10~14개로 사용자를 파악한 뒤, md 폴더(로컬 git) + 규칙 파일 + 스킬 3개 + 자동 작업(훅) 7개(선택 2개 더) + 도구 4개 + 시험 17개를 **직접 만들어** 준다. 화면·서버·검색 색인은 없다.
- **가장 큰 차이 — 자동으로 써도 되는 곳의 경계.** 교수님은 "자동으로 쌓이는 것은 일지와 **제안**뿐, 위키 지식·규칙은 사람이 고른 것만"이다(§1). 우리는 AI가 쓴 초안이 확인 전에도 검색·미리 넣기에 쓰이고, 실수 노트는 안전 검사만 통과하면 바로 적용된다.
- **꼭 가져올 것**: ① 초안을 지식과 분리(확인 전에는 제안으로만) ② 결정 변경은 저장 순간의 찾기가 아니라 **주기 정리**(일지와 페이지를 대조, 근거 인용 확인, 사람이 고름)로 잡기 ③ 규칙은 **개수 상한 + 범위**로 줄이기 ④ 제안을 사람에게 보이기 전에 "이미 있음·합칠 곳"을 미리 검사.
- **우리가 더 나은 것**: 한국어 검색 엔진과 측정 숫자(recall@5 96.7%, 쓰는/안 쓰는 216번 비교), 앱 화면(그래프·정리 보드·편집), 회귀 시험이 있는 교정, 버튼 하나 설치, 같은 코드로 같은 결과.
- **뿌리가 같다 (11/13 추가, 추정)**: 교수님 프롬프트는 Karpathy "LLM Wiki" gist의 구조(원본·위키·규칙 파일, ingest·query·lint, `index.md`·`log.md` 형식)를 그대로 따른다. 우리 설계도 같은 gist를 아이디어로 참고했다(설계서 11절). 같은 뿌리에서 교수님은 자동 수집과 사람 승인 쪽으로, 우리는 검색 엔진·앱 화면·교정 검증 쪽으로 넓혔다(12절 "그래프 보기").
- **보완 뒤 차별점 한 문장**: 교수님 방식의 "자동은 제안까지, 확정은 사람이" 원칙을 따르면서, 그 확인을 앱의 정리 보드 한 곳에서 끝내고 효과를 숫자로 보여 주는 세컨드 브레인.

## 2. 분석 방법과 교수님 구성 요소

분석 방법(그대로 따름):

1. 교수님 프롬프트를 스킬·파일 단위로 읽는다(아래 2-1).
2. 수업에서 들은 것(가설)을 프롬프트로 확인한다(3절 H1~H10).
3. 같은 축으로 대조한다(4절).
4. 숫자로 비교할 수 있는 것은 같은 방법으로 잰다. 계획만 세우고, 재는 것은 사용자가 정한 뒤 한다(9절 측정 계획).
5. 우리 판단과 교수님 판단이 다르면 둘 다 적는다. 우리 실측이 있으면 근거로 붙인다.

### 2-2. 설치 때 묻는 질문 (메일의 "페르소나 질문 10~14개")

메일 본문: "페르소나를 위한 질문이 10~14개 있으니 자세하게 답하라." 프롬프트 §0의 질문이다. 세 묶음으로 한 묶음씩 묻고, 모든 답을 들은 뒤에야 만들기 시작한다. 2묶음은 기본값으로 넘길 수 있고 나머지는 건너뛸 수 있다.

| 묶음 | 질문 (요지) | 답이 쓰이는 곳 |
|---|---|---|
| 1. 나에 대해 | (1) 지금 상황과 일(학생·직장인·프리랜서·구직·기타 + 전공·역할 한 줄) (2) AI 에이전트·터미널을 쓰는 정도(처음·가끔 질문·매일 일에·여러 에이전트와 자동화) | 학생이면 업무 구분 없이 `personal` + 과목별 `study/`. 익숙함에 따라 설명 길이 |
| 2. 설치 | (3) 연결할 도구(Claude Code·Codex·Gemini CLI/agy) (4) 두뇌 폴더 위치(기본 `~/.brain`) (5) 쓰기 언어(기본 영어) (6) 선택 기능 a 업데이트 요약·b 메일 정리 | 스크립트 기본 경로, 쓰기 언어, 자동화 여부 |
| 3. 무엇을 넣나 | (7) 진행 중인 프로젝트 폴더 1~3개(학생이면 과제·개인 프로젝트) (8) 주로 남길 것(프로젝트 진행·배우는 기술·조사 자료·업무 결정과 일지) (9) 답 방식(짧게 결론 먼저·자세히 단계별) (10) 절대 쓰면 안 되는 것 | 설치 직후 프로젝트 페이지 생성, harvest 우선순위, 전역 블록 한 줄, 금지 목록 |
| 고급 (원하면) | (11) 지금 배우거나 이루려는 것 1~3개 (12) 주 언어·도구·플랫폼 (13) 일하는 방식(먼저 묻기·알아서 하고 끝에 보고) (14) 지금 노트를 두는 곳(Notion·Obsidian·메모 앱·없음) | `me.md`, `dev` 목차 머리, 전역 블록 |

- 묻지 않는 것: 나이·성별·건강·가족. 답에 나와도 `me.md`에 옮기지 않는다.
- 답은 `<brain>/me.md`에 **말한 그대로만** 적는다(추측 추가 금지).
- 이 질문에 답하는 일은 교수님 시스템을 실제로 설치할 때 필요하다(12절 "직접 써 보기"). 우리 제품의 연동 화면에는 이런 질문이 없다(9절 P7).

## 3. 수업에서 들은 것 (가설) → 프롬프트로 확인

| # | 들은 것 (사용자 전달) | 결과 | 프롬프트에서 확인한 것 |
|---|---|---|---|

| H9 | 실수 노트 수백 개는 **AI마다 decision** 또는 **교정 에이전트** (K-41 답) | **부분 맞음** | 교정 에이전트 = dream(교정·선호 → 규칙 후보) + `brain-verify.py`(다른 모델 검사). 규칙은 **늘어나지 않게** 막는다: 전역 30줄 상한(넘으면 멈추고 사람이 합칠 줄을 고름), 설명·파일 범위가 필요한 규칙은 `~/.claude/rules/<이름>.md`(`paths:` — Claude Code 기능, 공식 문서 미확인), 프로젝트 규칙은 그 프로젝트 메모리, 7일마다 합치기·고치기·지우기 제안(§4, §5, §6). "decision"이라는 파일·장치는 없다. 가까운 것은 프로젝트 페이지의 `## Key decisions`(날짜·결정·이유)이고, "AI마다"는 도구별 전역 파일을 말한 것일 수 있다(**미확인**) |
| H10 | `init` 프로젝트 등 스킬이 많다 | **다름** | 스킬은 3개(`/inbox`, `/init-project`, `/mail` 선택)뿐이다. 많은 것은 **자동 작업**이다: 훅 7개(선택 2개 더), 도구 4개(§5, §6) |

## 6. 교수님 시스템의 최적화 방식

| 줄이는 것 | 교수님 방법 | 우리 대응 |
|---|---|---|
| 늘 읽는 글 (토큰) | `AGENTS.md`는 늘 지킬 규칙만, 가끔 하는 일은 `guide/`에서 그때만 연다(§3). 전역 블록은 몇 줄, 규칙은 30줄 상한(§4) | 세션 시작 안내 2,615자(규칙 15개), 세션마다 같은 글이라 캐시 재사용. 규칙 40개면 3,518자(K-41 측정) |
| 찾기 (토큰·턴) | 목차 → 절 목차(50줄 넘으면 나눔) → 페이지, `rg -il`은 파일 이름만(§3, §4) | `find` 5줄 평균 약 480자, `show id#섹션`, 턴 2.9 → 2.0, 입력 토큰 −31% |
| 큰 파일 통째 읽기 | `log.md`는 덧붙이기(`cat >>`)만, 볼 때는 `grep`·`tail`(§3) | `_log/`는 앱·CLI가 읽고 AI는 통째로 안 읽는다 |
| 세션 문맥 | 맞는 프로젝트 하나의 상태·할 일만 3,500자까지(§6). 끝난 할 일은 지워서 짧고 정확하게(§3) | 프로젝트와 무관한 같은 안내 |
| 배경 호출 비용 | 자주 도는 일은 haiku, 판단은 sonnet. `--tools ""`·`--setting-sources project`·세션 저장 안 함. 새 대화가 없으면 호출 안 함. `grep -F`로 먼저 거르고 입력 상한(20KB·120KB·250KB·60KB·묶음 100KB)(§1, §6) | 자동 정리: 하루 달러 상한, 짧은 세션부터, 사용자 문장 150개 넘는 세션 건너뜀 |
| 회고 | 한 단계 아래 회고만 읽음 → 몇 년이 지나도 한 번에 읽는 양이 작다(§6) | `brain review`는 기간 변경 기록만 |

## 7. 우리가 더 좋은 점 / 우리만 있는 기능 (교수님 쪽 확인 뒤)

- **실측 근거**: 쓰는 사람 vs 안 쓰는 사람 216번 실측(지난 결정 질문에 맞게 답한 것 2 → 24번), 검색 recall@5 96.7%(질문 30개), 주입 시험 16번 중 따름 0번, K-41·K-42 약점도 숫자로 잼. 교수님 프롬프트에는 품질·토큰 측정이 없다(동작 시험만).
- **한국어 검색 엔진**: 공백 무시 2글자 분할 FTS5 + BM25 + 한영 표기 사전. 노트 1만 개에서 찾기 38ms. 교수님은 `rg` 문자열 일치.
- **질문별 규칙·노트 연결**: 요청마다 맞는 실수 노트(최대 3개)와 확실한 노트를 붙인다. 교수님은 질문 단위로 넣는 것이 없다(세션 시작 프로젝트 문맥만).
- **화면**: 그래프·정리 보드·노트 편집·배운 것·할 일을 갖춘 macOS 앱. 비개발자도 지식을 보고 고친다. 교수님은 폴더뿐이다.
- **설치**: [연동] 버튼 하나. 교수님은 질문 10~14개 + AI가 스크립트를 만드는 시간·토큰이 든다.
- **교정의 회귀 시험**: 규칙끼리 부딪히면 거절한다. 교수님은 다른 모델 검사 + 사람 승인뿐이다.
- **쓰기 안전**: 원자적 쓰기, 기대 해시로 충돌 확인, 폴더 밖 쓰기 막기, 실수 노트 내용·근거 검사. 교수님은 git 잠금과 "편집 직전 다시 읽기".
- **앱 안 AI 질문과 요금제**: 서버 게이트웨이(크레딧 예약·정산). 교수님은 서버가 없다.
