## 3. 설계서 밖에서 생긴 남은 작업

중요도 순. **높음**은 2주차 안, **중간**은 3주차 안, **낮음**은 시간이 남으면.

| 중요도 | 할 일 | 이유 |
|---|---|---|
| 높음 | 축약본 길이 줄이기 | 이 세션 하나가 축약 뒤에도 147,714자(메시지 241개). 지난 대화 자동 정리가 사용자 토큰을 크게 쓴다. AI 긴 답은 앞 몇 줄만, 코드 블록 생략, 세션당 상한(예: 3만 자) 후 "나머지는 사용자 문장만" 같은 단계 축약을 정하고 3주차에 비용을 잰다 |
| 높음 | 정리 비용 어림과 상한 | 대화 17개 세션이 약 $0.40·50초. 저장 안 한 세션이 27개이고 대화 787개짜리도 있어 전부 돌리면 수십 달러가 될 수 있다. 동의 화면에 어림 비용, 세션당 상한(예: 대화 200개 넘으면 사용자 문장만), 큰 세션은 따로 고르게 한다 |
| 높음 | 본문의 명령 예시가 권한에 걸림 | 노트 본문 heredoc에 `ln -s` 같은 명령 줄이 있으면 화면 없는 실행에서 `brain add`가 거절됐다(AI가 명령 줄을 빼고 다시 저장). 본문을 파일·base64로 넘기는 옵션(`brain add --body-stdin-b64` 등)이나 권한 규칙을 확인 |
| 높음 | NFC 정규화 | Dart 기본 라이브러리에 없다. 맥 파일 이름은 NFD로 올 수 있어 제목·검색어 비교가 어긋날 수 있다. 패키지(`unorm_dart` 등, 라이선스 확인) 선택 |
| 높음 | 정리 전 비용·시간 미리 보기 | 동의 화면에 "세션 N개, 약 몇 자"만 보인다. 축약본 글자 수 합과 세션당 평균 비용(시험 값)을 함께 보여 준다 |
| 높음 | 보완 노트 처리 | 스킬은 중복이면 `보완: <제목>` 초안을 만든다(설계의 `brain write --expect-hash` 대신, 사용자 확인을 거치게). 앱 정리 대기에 "원래 노트에 합치기" 버튼이 필요하다 |
| 중간 | Codex 연동 (미결정 7) | Codex 세션 형식(`~/.codex/sessions/.../rollout-*.jsonl`) 파서, 스킬 설치 위치, `codex exec` 화면 없는 실행, 훅 승인(`/hooks`) 안내 |
| 중간 | 제외 프로젝트 저장 | 지난 대화 카드의 체크 해제가 화면 상태로만 남는다. `_meta/session_excludes.json` 같은 곳에 저장해 다음에도 뺀다 |
| 중간 | 화면 없는 실행의 부작용 줄이기 | `--bare`는 구독 로그인(OAuth)을 읽지 않아 못 쓴다. 그래서 사용자의 다른 훅·MCP도 함께 뜬다. `--strict-mcp-config`로 MCP를 끄고, 우리 플러그인만 쓰게 하는 방법을 확인 |
| 중간 | 한 번에 여러 세션 | 지금은 하나씩 순서대로. 세션이 많으면 오래 걸린다. 2~3개 동시 실행 옵션과 앱을 닫아도 이어 하기 |
| 중간 | 앱 색인을 별도 isolate로 | 노트 화면의 `sync()`가 화면 스레드에서 돈다. 노트가 많아지면 버벅일 수 있다 |
| 중간 | 앱 빌드 순서 자동화 | `bash tool/build_brain.sh`를 먼저 해야 앱 자산에 `brain`이 들어간다. Xcode Run Script나 `make` 한 줄로 묶는다 |
| 중간 | 터미널에서도 `brain` 쓰기 | 지금 `brain`은 Claude Code 안(플러그인 `bin/`)에서만 PATH에 있다. 연동 화면에 "터미널에서도 쓰기"(`~/.local/bin/brain` 링크) 선택지 |
| 낮음 | 해제 때 파일 정리 | [해제]는 플러그인 등록만 지우고 `~/Library/Application Support/com.konga22.secondbrain/claude-code/`는 남긴다 |
| 낮음 | Intel 맥 | `brain`을 arm64로만 빌드한다. 필요하면 x64 빌드를 더한다 |
| 낮음 | 비밀값 가림 오탐 | `password: 1234` 같은 문장도 가린다. 2주차 가림 시험 사례에 넣는다 |
| 낮음 | 세션 id 8자 겹침 | 앞 8자가 같은 세션이 생기면 `find`가 첫 번째만 고른다. 겹치면 더 길게 쓰게 안내 |

## 7. 지식 추출 품질: 약점과 시험 계획 (2026-11-06 추가)

지금 "무엇이 지식인가"는 `brain-save` 스킬 규칙(설계서 5.6절)을 읽은 AI가 판단한다. 아래 다섯 질문을 통과하면 노트로 남긴다.

1. 다음 세션이나 다른 프로젝트에서 다시 쓰는가
2. 이 대화가 끝나도 맞는가
3. 테스트·측정·사용자 결정으로 확인됐는가
4. 코드만 봐서는 모르는 "왜"인가
5. 노트 하나만 읽어도 이해되는가

이 규칙이 실제로 잘 맞는지는 아직 재 보지 않았다. 아래 약점은 2~3주차에 시험해서 결과를 이 표에 적는다.

| 번호 | 약점 | 시험 방법 | 통과 기준 (안) |
|---|---|---|---|
| W1 | **판단 정확도를 모른다.** 쓸모없는 노트가 섞이거나, 남겨야 할 것이 빠져도 알 수 없다 | 짧은·중간·긴 세션 10개(프로젝트 섞기)를 정리 → 사용자가 노트마다 쓸모 있음/없음/틀림을 표시하고, 세션마다 "이건 남았어야" 목록을 적는다 | 쓸모 있음 80% 이상, 틀린 내용 0개, 빠진 것 세션당 1개 이하 |
| W2 | **근거가 세션 단위뿐이다.** `sources`에 축약본 파일만 있고 몇 번째 줄인지 없다. 노트의 주장이 대화에 정말 있었는지 따라가기 어렵다 | 노트 20개를 무작위로 골라 본문의 주장마다 축약본에서 근거를 찾는다 | 근거를 못 찾는 주장 5% 이하. 넘으면 `brain add --evidence <글자 범위>`처럼 근거 위치를 남기는 옵션 추가 |
| W3 | **확인 단계를 건너뛸 수 있다.** 11/06에 사용자 요청으로 AI가 [확인]을 대신 눌러 초안 12개(n_0008~n_0019)가 검토 없이 정리됨이 됐다. 지금은 누가 확인했는지 남지 않는다 | 그 12개를 사용자가 다시 읽고 W1 기준으로 표시한다 | 결과에 따라 frontmatter에 `confirmed_by: user\|ai`를 남기고, AI가 확인한 노트는 표시를 붙인다 |

## 6. 공식 문서로 확인한 것 (2026-11-06)

- Claude Code 플러그인은 `claude plugin marketplace add <로컬 폴더>` → `claude plugin install <이름>@<마켓>`으로 설치되고, 로컬 폴더는 복사 없이 그 자리에서 읽힌다. 플러그인 `bin/`은 켜져 있는 동안 Bash 도구 PATH에 들어간다 → 미결정 8(Claude Code 쪽) 답.
- 훅 표준 입력: `session_id`, `transcript_path`, `cwd`. SessionEnd 훅은 모두 합쳐 1.5초(타임아웃을 주면 최대 60초). SessionStart·UserPromptSubmit은 `hookSpecificOutput.additionalContext`로 10,000자까지.
- Stop 훅은 `{"decision": "block", "reason": …}`으로 Claude를 계속 일하게 할 수 있다 (`stop_hook_active`로 반복 방지) → 미결정 10: 가능은 하지만 방해가 커서 5절 대안을 권장.
- 화면 없는 실행: `claude -p … --permission-mode dontAsk --allowedTools "Bash(brain *)" --no-session-persistence --output-format json`. `--bare`는 OAuth·키체인을 읽지 않아 구독 사용자는 못 쓴다 → 미결정 11 답.
- Claude Code 대화 기록 보존: `cleanupPeriodDays` 기본 **30일** (설계서의 "약 30일로 알려짐" 확인).
- 스킬 frontmatter `allowed-tools: Bash(brain *)`로 스킬이 불릴 때 `brain` 명령을 묻지 않고 실행한다. 스킬 본문의 `${CLAUDE_SESSION_ID}`는 지금 세션 id로 바뀐다.
