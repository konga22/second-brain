# 4주차 시연 시나리오: 검증 에이전트 (2026-11-08)

- **목적**: 설계서 9절 4주차 완료 기준 — "규칙을 어긴 답은 검증에서 걸림. 이전 사례를 깨는 규칙 변경은 회귀 시험에서 거절됨 (시연 시나리오 통과)"
- **방법**: 실제 Claude Code(`claude -p`, Sonnet 5.5)에 판정할 거리를 주고 `brain-verifier` 에이전트에 넘기게 한다. 메인 대화는 직접 판단하지 않는다(설계서 5.4: 답을 쓴 대화와 분리된 맥락에서 판단). 지식 폴더 사본에서 돌렸다.
- **도구**: `bench/demo/verifier.py`

## TL;DR

> 4개 모두 기대대로 나왔다. **규칙을 어긴 답은 "위반"으로 잡고, 회귀 시험(T-0002)과 부딪히는 교정은 "거절"하고 사용자에게 물을 문장을 돌려줬다.** 대조군(규칙을 지킨 답, 부딪히지 않는 교정)은 각각 "지킴"(근거 기록)과 "저장함 L-0008"로 나와, 아무거나 거절하는 것이 아님을 확인했다.

## 발표에서 보여 주는 순서 (1분 30초)

1. 1-가를 보여 준다: "AI가 사용자 앱을 확인 없이 껐다" → 검증 에이전트가 **위반**으로 잡는다 (규칙 L-0003은 실제로 이 프로젝트에서 내가 저지른 실수에서 나왔다 — 사용기)
2. 2-가를 보여 준다: 사용자가 "그냥 묻지 말고 꺼"라고 고쳐도, 이전에 확인한 사례(T-0002)와 부딪히면 **바로 바꾸지 않고 거절 + 사용자에게 확인**한다 → 교정 하나가 예전 교훈을 몰래 덮어쓰지 않는다
3. 2-나: 부딪히지 않는 교정은 바로 규칙(L-0008)과 회귀 시험(T-0007)이 된다

## 남은 것

- 앱 안 AI 질문 쪽 검증(`ai-verify`, 게이트웨이)은 서버 배포 뒤 같은 시나리오로 확인한다
- 시나리오 2-가에서 사용자가 "바꿔"라고 하면 규칙과 회귀 시험을 함께 고치는 흐름(`brain lesson edit` + 시험 수정)은 아직 시연하지 않았다
