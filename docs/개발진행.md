### 앱 랙 최적화 검토 (11/07, 조사 중 · 코드 수정 없음)

사용자: "데스크탑 앱이 랙 걸려, 최적화 검토하고 최적화할 만한 깃허브 찾아 줘".

잰 것 (노트 38개 실제 지식 폴더, CLI·코어 시간):

| 작업 | 시간 | 언제 도나 |
|---|---|---|
| `Linter.run` | 11.3ms | 지식 폴더가 바뀔 때마다(`lintIssuesProvider`) |
| `LessonStore.all` | 약 3ms | 바뀔 때마다 |
| `LessonStore.match` | 약 2.6ms | 훅 1번 |
| `TodoStore.candidatesFromNotes` | 약 3ms | 할 일 화면 그릴 때 |
| `TodoStore.fromNotes` | 약 1.8ms | 할 일 화면 그릴 때 |
| `SearchIndex.sync` | 2.3ms | 바뀔 때마다 |

→ 코어 계산은 한 번에 수 ms라 **랙의 주원인으로 보기 어렵다**. 의심 원인 (코드 읽기로 찾음, 아직 측정 전):

1. **디버그 빌드(JIT)로 띄움** — `flutter run` 기본이 debug라 그리기가 몇 배 느리다. profile 모드와 비교부터 해야 진짜 랙인지 안다
2. **그래프 그리기**(`home/graph_view.dart`): 노드마다 `MaskFilter.blur`(번짐) + 매 프레임 `TextPainter` 새로 만들기, 마우스를 올릴 때마다 `setState`로 GraphView 전체 다시 그리기
3. **구조 목록**(`home/structure_list_view.dart`): 스크롤 이벤트마다 `_measure` → `setState`
4. **빌드 중 파일 읽기**: 오른쪽 패널·사이드바·할 일이 그릴 때마다 디스크를 읽는 곳이 있음
5. 지식 폴더가 바뀔 때마다 점검(`Linter`)·실수 노트·할 일 후보를 전부 다시 계산 (자동 저장·자동 정리로 바뀜이 잦아짐)

다음 순서:

1. `flutter run --profile -d macos`로 띄워 DevTools 성능 탭에서 그래프 끌기·확대, 목록 스크롤, 화면 전환의 프레임 시간(UI/Raster) 재기 → 숫자를 이 표에 추가
2. 그래프: `TextPainter` 캐시(제목·배율이 같으면 재사용), 번짐 빼거나 미리 그린 그림 재사용, 마우스 올림은 `ValueNotifier` + `CustomPaint(repaint:)`로 그리기만 다시, `RepaintBoundary`
3. 구조 목록: `_measure`를 프레임당 한 번으로(`addPostFrameCallback` 모으기), 값이 같으면 `setState` 안 함
4. 빌드 중 파일 읽기를 provider로 옮겨 지식 폴더 번호(revision)별로 한 번만
5. 점검·할 일 후보는 화면이 보일 때만 계산(`autoDispose`), 필요하면 isolate (최상위 함수만, L-0004)
