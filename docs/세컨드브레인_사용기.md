# 세컨드 브레인 사용기 (개발하며 직접 써 본 피드백)

- **목적**: 개발하는 AI(Claude Code)가 실제로 `brain` 명령으로 지식을 찾고 저장하면서 느낀 불편·장점을 적는다. 사용자 입장의 문제를 일찍 찾기 위해서다.
- **쓰는 법**: 날짜, 상황, 무엇이 불편/좋았나, 원인, 조치(고침·과제)를 한 항목에 적는다. 고친 것은 `(고침)`을 붙인다.

## 2026-11-06

| # | 상황 | 느낀 점 | 원인 | 조치 |
|---|---|---|---|---|
| 1 | `brain find 검증 에이전트` | 요약이 40자에서 잘려 "회귀 시험 통과 …"처럼 끝이 안 보였다. 요약은 60자 한 줄이 목적인데 결과에서 잘리면 노트를 또 열어야 한다 | `find`가 `clip(summary, 40)` | (고침) 60자 그대로 출력. 5줄 기준 토큰 증가는 작다 |
| 2 | NFC 작업 전 `brain find NFC`, `정규화` | 찾은 것 없음. 이 주제의 지식이 아직 없어서 정상. 대신 "찾은 노트 없음 (검색어를 바꿔 보세요)"가 다음 행동을 알려 줘서 좋았다 | - | - |
| 3 | 자연어 질문 20개로 bench | 처음 15%만 찾았다. "웹훅이 실패하면?"이 "웹훅을 다시 보낸다"를 못 찾음. AI는 키워드로 찾으니 경로 A에선 덜 보이지만, 앱 안 질문(경로 B)은 자연어라 치명적 | 검색어 "웹훅이"를 그대로 구절로 찾고, 모든 단어 AND | (고침) 조사·어미 떼기 + 느슨한 채우기 → 95% |
| 4 | 추천 연결 확인 | 같은 주제(게임AI) 두 노트가 안 이어지고, "플러그인 설치 ↔ FAT32 USB" 같은 약한 연결은 생겼다 | 자기 점수 대비 비율 기준 | (고침) 핵심 단어 2개 이상 겹침 기준. 그래도 "로컬 우선 구조 ↔ 타이쿤 게임" 같은 약한 연결이 남음 → 과제: 노트가 100개 넘으면 bench식 연결 시험 |
| 5 | bench 놓침 "엑스코드 꼭 설치해야 해?" | 노트엔 "Xcode"만 있다. 한글 표기로 물으면 못 찾는다 | 표기 차이. 설계의 `aliases`가 답인데 `brain add`에 별칭 옵션이 없어 AI가 별칭을 못 넣는다 | (고침) `brain add --aliases`, `brain-save` 스킬에 "영어·한글 표기가 다르면 별칭" 규칙. 이미 저장된 노트는 별칭이 없음 → 과제: `brain write`로 별칭 추가하는 방법 |
| 6 | `brain show` | 끝에 `연결:` 줄이 생기니 다음에 열 노트를 바로 고를 수 있었다. 토큰은 한 줄 | - | 유지 |
| 7 | `brain find` 결과의 `[초안]` | 확인 안 된 지식을 구분할 수 있어 근거로 인용할 때 조심하게 된다 | - | (고침) 스킬에 "(초안 n_0042)처럼 밝힌다" |
| 8 | `brain lesson 커밋해 줘` | "커밋하거나 push할 때" 규칙을 못 찾았다. 짧은 요청일수록 규칙이 안 걸리는 건 훅의 목적과 반대 | 2글자 조각 전체 비교라 겹치는 조각이 1개뿐 | (고침) trigger 단어 머리 비교 |
| 9 | 훅 교정 신호 "아니야 그게 아니라 다시 해" | 안내가 안 나왔다 | 정규식 `\b`가 한글 뒤에서 동작 안 함 | (고침) 뒤에 공백·문장부호·끝이 오는지로 판단. 한글 정규식에 `\b` 쓰지 않기 |
