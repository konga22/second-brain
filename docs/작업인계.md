## 4. 사용자 규칙·선호 (반드시 지킬 것)

- **답변·보고는 한국어**. 코드·경로만 원문. 교수님 메일·보고는 회사식, 서명 "김민상 올림". 문서는 Word로 쓰고 PDF로 보냄.
- **커밋·push·PR은 매번 명시적 허락**을 받는다. 커밋 메시지 한국어, 접두사 `feat/bug/perf/refactor/misc`, 작업별로 커밋을 나눈다. 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **브랜치**: `feat/` `bug/` `perf/` `refactor/` `misc/` 접두사. **main에 직접 push 금지** (첫 push만 빈 레포라 예외였음). push는 `로컬:원격` refspec으로.
- **PR**: draft, 한국어, 제목 `접두사: 제목`, 본문 고정 절(TL;DR / 배경/맥락 / 관찰된 문제 또는 목표 / 수정 방향 / 수정된 파일 / 검증 기준 / 테스트 목록 / 공식 문서 또는 참고 자료). 기준 브랜치는 물어본다(지금까지 main). 끝에 `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. merge는 사용자가 "merge해 줘"라고 할 때만, merge 커밋 방식으로.
- **스크린샷은 사용자가 "찍어서 보여 줘"라고 할 때만** 찍고 보낸다. 화면 확인은 DOM 검사로.
- **넘겨짚지 않기**: 찾은 자료를 프로젝트에 연결하거나 범위를 바꾸기 전에 먼저 묻는다.
- **설계 변경은 설계서에만**. 기획안은 사용자가 요청할 때만 다시 만든다.
- 메일·메시지 발송, 삭제, 계정·설정 변경은 허락 없이 하지 않는다. 계정 만들기·API 키 입력은 사용자가 직접 한다(키는 Supabase 함수 환경변수에만).
- 지식 데이터는 기기에만, 서버 테이블·로그에 저장하지 않는다. 요금제 판단은 서버에서. 참고한 오픈소스는 출처·라이선스를 남긴다.
- 무료/유료 경계 같은 미정 사항은 혼자 정하지 않는다.
