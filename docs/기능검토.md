# 주요 기능 검토: 약점·필요한 시스템·아이디어

- **작성일**: 2026-11-06 (M1~M4 개발 직후) · **갱신**: 2026-11-08 — [4절 약점 극복 기록](#4-약점-극복-기록-찾은-약점--고친-방법--시험-기록) 추가 (약점마다 고친 방법·시험 기록·상태)
- **목적**: 직접 만들고 써 보면서 본 주요 기능의 약점과, 이 플랫폼에 필요해 보이는 시스템·아이디어를 남긴다. 설계서에 넣을지는 사용자가 정한다.
- **관련 문서**: [개발진행](개발진행.md) · [남은작업](남은작업.md) 7절(지식 추출 W1~W6) · [사용기](세컨드브레인_사용기.md)

## TL;DR

- **잘 된 것**: 검색은 자연어 질문 20개에서 recall@5 95%(고치기 전 15%), 훅은 10ms에 관계없는 요청이면 0토큰, 그래프는 저장 위치로 바로 그린다.
- **가장 큰 약점 3개**:
  - 지식 추출과 규칙 매칭이 모두 "AI 판단 + 단순 규칙"이라 정확도를 아직 재지 않았다.
  - 서버(AI 게이트웨이)는 코드만 있고 한 번도 실행하지 않았다.
  - 휴지통·되돌리기 사본이 지워지지 않고 쌓인다.
- **먼저 만들 시스템**: 추출·연결 품질 측정(bench 확장), 근거 줄 남기기, 되돌리기·휴지통 화면.
- **11/08 갱신 — 극복한 약점 8개, 남은 약점 2개 새로 찾음** (4절):
  - 검색: 30문항 recall@5 96.7%.
  - 노트 1만 개: 목표 6개 모두 통과.
  - 노트 속 지시: 따름 0/16.
  - 같은 실수 상황: 6/12 → 11/12.
  - brain 명령 파이프 거부: 12/54 → 0/54.
  - 1-1·1-4의 약점 줄 끝에 극복 상태를 달았다.

## 1. 기능별 검토

### 1-1. 검색 (경로 A `brain find`, 경로 B 근거 찾기)

- **지금**: 2글자 분할 + 조사·어미 떼기(약 40개) + 결과가 모자라면 느슨한 채우기. 질문 20개에서 recall@5 95%, MRR 0.835, 0.49ms.
- **약점**
  - (11/08 결정: 2글자 분할 유지, 미결정 1) 조사 규칙이 단순하다. "하는"을 떼면 "모하는"(모하다?) 같은 말도 잘린다. 2글자 이상 남을 때만 떼서 피해는 작지만 형태소 분석기보다 거칠다(미결정 1).
  - 느슨한 채우기는 정확도를 조금 깎는다. 단어 하나만 맞는 노트가 5개 안에 들어올 수 있다. 경로 B는 그 노트가 그대로 AI에게 간다. → **(11/07 경로 A 극복, K-02)** 약한 후보는 숨기고 "확실한 노트 없음". 경로 B는 서버 배포 뒤
  - 표기 차이(Xcode↔엑스코드)는 별칭이 있어야 풀린다. 이미 저장된 29개 노트에는 별칭이 없다. → **(11/08 극복, K-01)** 개발 용어 한영 표기 사전 60개(양쪽 방향)
  - 질문 세트가 20개, 노트가 29개뿐이다. 노트 1만 개에서 검색 속도·정확도는 아직 안 쟀다(3주차 계획). → **(11/07~08 극복, K-01·K-03)** 질문 30개·노트 47개 96.7%, 노트 1만 개 `find` 43ms
  - **(11/08 새로 찾음, K-09 남음)** 훅이 미리 넣는 노트(R2)가 흔한 단어(서버·다시·앱·화면)만 겹쳐도 붙는다: "포트 8080… 다시 켜 줘"에 한반도감 재구축 노트
- **필요한 것**: bench 질문 30개 이상(사용자 준비), 1만 노트 샘플 생성기, 경로 B는 BM25 점수 기준값을 둬서 약한 결과는 보내지 않기.

### 1-2. 지식 추출 (`brain-save`, 지난 대화 정리)

- **지금**: AI가 스킬 규칙(다시 쓰나·오래 가나·확인됐나·코드로 모르나·혼자 읽히나)으로 판단. 긴 세션 하나 163,624자 → 175초·$2.35·노트 10개.
- **약점**: [남은작업](남은작업.md) 7절 W1~W6 그대로. 여기에 더해
  - **비용**: 축약본 10만 자당 약 $1.4(실측). 연동 때 지난 대화 27개를 다 돌리면 수십 달러가 될 수 있는데, 동의 화면에는 세션 수만 보인다.
  - **세션당 10개 상한**: 긴 세션은 상한에 걸려 빠지는 것이 생긴다(실제로 2차 추출이 10개에서 멈춤).
  - **세션 사이 중복**: 같은 주제를 여러 세션에서 다루면 세션마다 비슷한 노트가 생긴다. `brain find`로 막지만 표현이 다르면 못 막는다.
- **필요한 것**: 동의 화면에 "약 N자 · 어림 $X" 표시(실측 단가), 긴 세션은 6만 자씩 나눠 여러 번 정리, 저장 뒤 중복 후보를 정리 대기에 함께 보여 주기.

### 1-3. 연결과 뇌 그래프

- **지금**: `[[제목]]` + 추천 연결(핵심 단어 5개 중 2개 이상 겹침). 노트 29개에서 추천 26쌍, 그래프는 주제별로 모여 그려진다.
- **약점**
  - 추천 연결의 근거가 2글자 조각이라 "로컬 우선 구조 ↔ 타이쿤 게임"처럼 약한 연결이 섞인다. 핵심 단어에 "이쿤"·"방학" 같은 단어 중간 조각이 들어간다.
  - 직접 연결(`[[ ]]`)이 0개다. AI가 노트를 저장할 때 링크를 걸지 않는다(스킬에 규칙이 없음).
  - 노드 1만 개 처음 배치가 12.5초(isolate라 화면은 안 멈춤). 노드 끌기, 큰 그래프 주제 묶기는 아직 없다.
- **필요한 것**: `brain-save` 스킬에 "저장 전 찾은 관련 노트는 본문에 [[제목]]으로 건다" 규칙, 핵심 단어는 단어 머리 조각만 쓰기, 연결 bench(사람이 정한 "이어져야 할 쌍" 대비 정밀도).

### 1-4. 실수 노트와 검증

- **지금**: (11/08 v1.3.16) 적용 중 실수 노트는 세션 시작에 한 줄씩 늘 보인다(최대 30개). 그와 별도로 trigger 단어 머리가 절반 이상 맞으면 요청마다 이유와 함께 넣는다(최대 3개). 교정 신호는 문장 첫머리 단어로 감지. 검증은 경로 A에서 `brain-verifier` 에이전트, 경로 B에서 `ai-verify`.
- **약점**
  - **(11/08 새로 찾음 → 극복, K-07) 안 걸림**: 반대로 사용자가 규칙과 다른 말로 요청하면 안 걸렸다. 6개 상황 중 2개만 걸려 지킴 6/12였다. 세션 시작 목록으로 11/12가 됐다
  - **헛걸림**: trigger가 "코드를 고칠 때"처럼 흔한 말이면 거의 모든 요청에 걸린다. 규칙이 늘면 토큰이 는다. (11/09 잼, K-12: 걸리면 안 될 요청 55개 중 3개·다른 규칙 1번, 관계없는 요청 0/10 — 작다. 대신 걸려야 할 요청도 55개 중 2개만 걸림)
  - **교정 신호**: 문장 첫머리만 본다. "음… 그게 아니라"나 "아니 근데"는 놓치거나 잘못 잡는다.
  - **(11/08 1차 확인, K-06)** **회귀 시험이 실제 실행이 아니다**: "새 규칙과 함께 적용했을 때 통과 조건을 만족하는가"를 AI가 판단한다. 결정적인 시험이 아니라서 같은 입력에 다른 판정이 나올 수 있다. → 시연 4개에서 기대대로 거절·저장했다. 같은 입력을 2번 돌려 판정이 같은지는 남음
  - **경로 A 의존**: `brain-verifier`를 부를지는 사용자 AI가 정한다. 안 부르면 교정이 그냥 사라진다.
- **필요한 것**: trigger에 흔한 말만 있으면 저장을 거절하거나 경고, 규칙별 "걸린 횟수" 기록(쓸모없이 자주 걸리는 규칙 찾기), 회귀 시험을 같은 모델로 2번 돌려 판정이 다르면 사람에게 넘기기.

### 1-5. 쓰기 안전 (원자적 쓰기·충돌·되돌리기)

- **지금**: 임시 파일 → 이름 바꾸기, 기대 해시, 작업 묶음별 되돌리기, 지우기는 휴지통으로.
- **약점**
  - `_meta/undo/`와 `_meta/trash/`가 지워지지 않고 쌓인다. 대량 가져오기·정리를 하면 지식 폴더가 커진다.
  - `_meta/conflicts/`에 충돌 사본이 생겨도 앱이 알려 주지 않는다.
  - 되돌리기 목록이 묶음 id만 보여 무엇을 한 묶음인지 모른다(사용기 #11).
  - 묶음 안에서 그 뒤 다른 묶음이 같은 파일을 고쳤으면, 앞 묶음을 되돌릴 때 뒤 변경까지 덮어쓴다.
- **필요한 것**: 되돌리기·휴지통 화면(묶음 요약, 30일 지나면 비우기 제안), 충돌 사본 알림, 되돌리기 전에 "그 뒤 바뀐 파일" 경고.

### 1-6. 서버 (AI 게이트웨이)

- **지금**: 마이그레이션·RLS·사용량 함수·함수 3개·앱 연동 코드. **배포·실행 시험은 아직**(이 맥에 Supabase CLI·Deno 없음).
- **약점**
  - 타입 검사도 못 했다. SDK 버전을 고정하지 않았다(`npm:@anthropic-ai/sdk` 최신). 처음 배포 때 버전을 고정해야 한다.
  - 노트 앞부분 500자가 그대로 나간다. 비밀값 패턴은 가리지만, 패턴에 없는 개인정보(주소·전화번호)는 나간다.
  - Haiku 5.5는 거절 시 서버 쪽 대체 모델이 없다. 거절되면 "답할 수 없습니다"만 보인다.
  - 월 한도만 있고 짧은 시간 연속 호출 제한이 없다.
- **필요한 것**: 배포 후 시험 시나리오(가입 → 질문 → 한도 → 모의 결제), 보내기 전 "이 노트들이 나갑니다" 미리 보기 옵션, 분당 호출 제한.

### 1-7. 앱 사용 흐름

- **약점**
  - 첫 실행 안내가 없다(폴더 고르기 → 연동 → 지난 대화 정리 순서를 사용자가 알아서 찾아야 함).
  - 노트 본문이 마크다운으로 그려지지 않고 글자 그대로 보인다. `[[링크]]`를 눌러 이동할 수 없다.
  - [대기 N개 모두 확인]이 검토 없이 정리됨으로 보낸다(W3와 같은 문제).
  - 그래프 이름표가 주제 이름과 겹친다.
- **필요한 것**: 첫 실행 3단계 안내, 마크다운 렌더링(링크 클릭), "모두 확인"은 노트를 한 번씩 연 것만.

## 2. 이 플랫폼에 필요해 보이는 시스템

우선순위 순. **높음**은 기말 전, **중간**은 시간이 되면, **낮음**은 2단계.

| 우선 | 시스템 | 무엇을 | 왜 |
|---|---|---|---|
| 높음 | 품질 측정 묶음 | `brain bench`를 검색 외에 추출(W1)·연결(정답 쌍)·규칙 매칭(걸려야 할 요청/걸리면 안 될 요청)까지 — **규칙 매칭·미리 넣기는 11/09 끝남**(`brain bench --lessons`, K-09·K-12). 추출·연결은 남음 | 지금 정확도 숫자가 검색 하나뿐이다. 발표에서 "얼마나 잘 되나"에 답하려면 필요 |
| 높음 | 근거 줄 | 노트 주장마다 축약본 글자 범위(`brain add --evidence`) | W2. 틀린 노트를 찾고 고치는 시간을 줄인다 |
| 높음 | 되돌리기·휴지통 화면 | 묶음 요약·되돌리기·비우기 | 안전장치가 있어도 사용자가 못 쓰면 없는 것과 같다 |
| 높음 | 정리 비용 어림 | 축약 글자 수 × 실측 단가($1.4/10만 자) | 연동 때 지난 대화 정리가 사용자 돈을 쓴다 |
| 중간 | 주간 회고 초안 | 타임라인(`_log/`)에서 그 주 새 지식·교정·결정을 모아 주간 보고 초안 md 생성 | 이 프로젝트 자체가 7일마다 보고한다. 세컨드 브레인의 쓸모를 바로 보여 주는 기능 |
| 중간 | 프로젝트 범위 검색 | `brain find --here`: 지금 작업 폴더에서 나온 노트를 먼저 | 노트가 늘면 다른 프로젝트 지식이 섞인다 |
| 중간 | 별칭 제안 | 개발 용어 영어↔한글 표기 사전(Xcode·엑스코드, Supabase·수파베이스 등)으로 저장 때 별칭 자동 제안 | bench 놓침의 대부분이 표기 차이 |
| 중간 | 규칙 사용 기록 | 훅이 규칙을 넣은 횟수·그 뒤 교정 여부 | 쓸모없는 규칙과 효과 있는 규칙을 가른다(evidence 자동 채우기) |
| 낮음 | 기기 안 모델 | 경로 B를 로컬 모델로도 | 노트를 기기 밖으로 아예 안 보내는 선택지 (미결정 6과 함께) |

## 3. 개발하며 직접 겪은 것 (근거)

- 검색 15% → 95%, 추천 연결 기준 두 번 바꿈, 규칙 매칭·교정 신호 버그: [사용기](세컨드브레인_사용기.md) #3·#4·#8·#9
- 이름 바꾼 파일 id가 바뀌던 색인 순서 버그, 링크 고치기가 끊긴 뒤 찾던 버그, 그래프 맞추기 좌표 버그: 모두 시험으로 찾아 고침([개발진행](개발진행.md) M3)
- 쓰는 사람 vs 안 쓰는 사람 비교(4조건 216번)에서 K-07·K-08·K-09·K-11을 찾음: [사용가치분석](사용가치분석.md), [사용기](세컨드브레인_사용기.md) #49
- 정리 시작이 멈춘 것처럼 보인 문제: 진행 표시·오류 처리 없이 기능만 만든 결과. 지금은 기본(오류 처리·진행 표시·실데이터 시험)을 먼저 넣는다

## 4. 약점 극복 기록 (찾은 약점 → 고친 방법 → 시험 기록)

- **규칙**: 약점을 찾으면 여기에 번호(K-xx)를 붙여 적는다. 고친 방법에는 설계서 버전과 파일을 적는다. 시험 기록에는 무엇을 몇 번 어떻게 돌렸고 전 → 후가 어땠는지 적는다. 고친 것이 다시 깨지지 않게 지키는 자동 시험도 적는다. 고치지 못했으면 "남음"으로 둔다.

### 4-2. K-07 시험 기록: 실수 노트가 다른 말로 한 요청에 안 붙음

- **날짜·환경**: 2026-11-08, macOS. Claude Code `claude -p`, 모델 Haiku 5.5, `--permission-mode dontAsk`, 허용 도구 `Bash(brain *)`·Skill·Read·Grep·Glob. 지식 폴더 사본(노트 50개·실수 노트 7개). 실제 지식 폴더·저장소·`~/.claude`와 다른 조건의 자료는 읽기 금지.
- **재현 명령**:

  ```bash
  bash bench/value/setup.sh <작업 폴더>
  VALUE_DIR=<작업 폴더> CMP_WORKERS=8 python3 bench/value/run.py m 2 <결과.jsonl> haiku D
  python3 bench/value/summary.py <결과.jsonl> bench/value/judge_20261108.json
  ```

- **시험 세트**: 실수가 다시 생길 상황 6개를 각각 2번 물었다. 끝에 "아직 손대지 말고, 어떻게 할지 순서만 3줄로 말해 줘."를 붙였다. 질문은 고치기 전에 썼다. 일부러 실수 노트의 상황 문장과 다른 말로 썼다.
- **판정**: 계획을 읽고 그 실수 노트의 행동이 있으면 1, 일부만 있으면 0.5, 없거나 그 실수를 그대로 하면 0으로 매겼다(사람 판정, `judge_20261108.json`).
- **원인 (고치기 전)**: 훅은 상황 문장(trigger)의 단어 머리가 요청에 절반 넘게 있어야 규칙을 붙인다. 예를 들어 "실행 중인 프로세스(앱 등)를 끌 때"의 단어 머리는 [실행·중인·프로]다. 그런데 "포트 8080을 다른 앱 프로세스가 잡고 있어… 끄고 다시 켜 줘"에는 "프로"만 있다(1/3). 그래서 붙지 않았다. `brain lesson "<요청>"`으로 6개 중 4개가 "맞는 실수 노트 없음"인 것을 확인했다.

### 4-5. 규칙 매칭 시험 기록 (K-09·K-10·K-12, 2026-11-09)

- **시험 세트** (`bench/lessons.yaml`): 매칭 결과를 보기 전에 썼다(L-0008).
  - 적용 중 실수 노트 11개마다 사용자 말투로 바꾼 "걸려야 할 요청" 5개와, 같은 단어가 있어도 그 상황이 아닌 "걸리면 안 될 요청" 5개를 뒀다. 예: L-0002에 "변경 사항 올려 줘"(걸려야 함) / "push 알림이 안 와"(안 됨).
  - 어느 규칙에도 걸리면 안 될 관계없는 요청 10개를 더했다. 모두 120개다.
- **실행**: `brain bench --lessons bench/lessons.yaml`. 돈이 들지 않고 결정적이다. 실제 지식 폴더에서 읽기만 한다.
  - 방식 비교는 `dart run tool/lesson_rules.dart`(실수 노트)와 `tool/inject_rules.dart`(미리 넣기)로 했다.
- **고르는 기준(재기 전에 정함)**:
  - 실수 노트: 헛걸림 10% 이하, 관계없는 요청 0번인 방식 중 걸림이 가장 높은 것.
  - 미리 넣기: 질문 세트마다 미리 넣는 질문이 1개 넘게 줄지 않고, 알려진 엉뚱한 사례와 관계없는 요청은 0개.

**실수 노트 (요청마다 붙는 매칭)**

| 방식 | 걸림 (55) | 헛걸림 (55) | 다른 규칙이 걸림 | 관계없는 요청 (10) | 기준 |
|---|---|---|---|---|---|
| S0 지금 (trigger 단어 머리 50%) | **2** | 3 | 1 | **0** | 통과(유일) |
| S1 trigger+행동에 단어 머리 2개 | 19 | 2 | 11 | 1 | 탈락 |
| S2 trigger+행동+diff에 단어 머리 2개 | 20 | 3 | 16 | 1 | 탈락 |
| S3 2글자 조각 검색(실수 노트만) 1등 + 단어 머리 2개 | 19 | 3 | 6 | 1 | 탈락 |
| S4 S0 또는 S1 | 20 | 4 | 12 | 1 | 탈락 |

- 넓히면 걸림이 10배가 되지만, 2글자 단어 머리라 "**리스**트"와 "**리스**너"처럼 뜻이 다른 말이 맞아 관계없는 요청에도 걸렸다. 다른 규칙이 잘못 걸리는 것도 6~16번으로 늘었다.
- **결정**: S0을 유지한다. 다른 말로 한 요청은 세션 시작 목록(K-07, 실측 11/12)이 맡는다. 비슷한 말 사전(토큰분석 P7)을 넣는다면 이 시험에서 S0보다 걸림이 높고 기준을 지킬 때만 넣는다.

**미리 넣기 (R2)**

| 방식 | 정식 질문 30개 (넣음 / 정답 포함) | 평소 말투 질문 14개 (넣음 / 정답 포함) | 알려진 엉뚱한 사례 (3) | 관계없는 요청 (10) | 작업 요청 (110) |
|---|---|---|---|---|---|
| V0 지금 (단어 머리 2개 이상) | 20 / 20 | 14 / 14 | 3 | 0 | 17 |
| V1 + 맞은 단어 비율 25% | 20 / 20 | 13 / **12** | **0** | 0 | 17 |
| V2 + 묻는 말 빼고 비율 25% | 20 / 20 | 14 / 14 | 0 | 0 | 19 |
| V3 + 긴 요청(단어 머리 12개 이상)만 비율 25% | 20 / 20 | 14 / 14 | 1 | 0 | 17 |

- V1은 기준을 숫자로는 통과한다. 하지만 정답을 놓치는 질문이 2개 생겼다. 카카오 봇 질문은 끝의 "짧게 답해 줘" 때문에 분모가 커져 22%였다.
- V2는 다 통과한다. 다만 카카오 봇 질문이 정확히 25%로 겨우 걸려, 말이 조금만 길어져도 놓친다.
- **결정: V0 유지.** 엉뚱한 노트는 데이터 경계와 함께 약 100~200토큰을 쓴다. 맞는 노트를 놓치면 AI가 찾기 턴을 한 번 더 써 약 3만 토큰이 든다(토큰분석 6.2). 놓치지 않는 쪽이 100배 넘게 싸다.
- **처음엔 V1을 넣었다가 되돌렸다**: 정식 질문 30개만 보고 V1을 코드에 넣었다. 그 뒤 평소 말투 질문으로 다시 재서 손해를 찾았다. 정식 질문 세트에는 "짧게 답해 줘" 같은 끝말이 없어 놓쳤다. 한 세트만으로 정하지 않는다(L-0008).
- 작업 요청 110개에 넣은 17번 가운데 약 절반은 관계있는 노트였다. 예: "Notifier에서 Isolate.run…" → n_0038, "허용 목록 때문에 명령이 안 돌아" → n_0014. 나머지 절반은 엉뚱했다. 예: "앱 다시 켜 줘" → 한반도감 재구축. 답 없는 질문 "도커 이미지 용량…"에 n_0002(회의록 앱 용량)가 붙는 것도 그대로다.

**자동 시험** (`cd packages/brain_cli && dart test` 10개 통과, `brain_core` 50개 통과)
- "말투가 길어도 맞는 노트는 미리 넣는다": 비율 기준을 넣으면 실패하는 것을 직접 확인했다(빈 통과 아님, L-0006).
